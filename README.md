# Хирургический фотоархив

Локальное Android-приложение для систематизации клинических фотографий по пациентам.

## Возможности

- Android 9+ (`minSdk 28`).
- Нозологические разделы каталога: создание, переименование и удаление. У пациента один основной раздел; старые записи доступны в «Без категории».
- Удаление раздела сохраняет пациентов и снимки, переводя пациентов в «Без категории».
- Поиск по ФИО и номеру карты внутри выбранного раздела.
- Карточка пациента: диагноз/клинический случай и краткая заметка.
- Четыре вкладки снимков: **До**, **Операция**, **После**, **Рентген**.
- Полноэкранный просмотр по нажатию: увеличение двумя пальцами 1–5×, перемещение увеличенного снимка, двойное касание 2.5×/сброс; доступны кнопки масштаба.
- Добавление снимков через системную камеру и множественный импорт из галереи.
- Краткое описание для каждого снимка.
- Удаление пациентов и фотографий.
- Фото хранятся в app-private `filesDir/clinical_images`; приложение не запрашивает доступ ко всему хранилищу и не имеет INTERNET permission.
- `allowBackup=false` и `FLAG_SECURE` для снижения риска утечки медицинских данных.
- Jetpack Compose Material 3 Adaptive `ListDetailPaneScaffold`: одна панель на узком телефоне, list-detail на планшете/раскрытом Fold, с учётом конфигурации окна и складных устройств.

## Сборка

Требуется Android Studio с JDK 17+ и Android SDK 36.

1. Откройте папку `ClinicalPhotoArchive` в Android Studio.
2. Дождитесь Gradle Sync.
3. Установите SDK 36, если Android Studio предложит это сделать.
4. Запустите на устройстве/эмуляторе Android 9+.

Проект использует AGP 9.3.1 и Gradle 9.5.0.

## Данные и резервные копии

Версия 1.4.0 обновляет Room 1→2 без перемещения файлов и без удаления данных.
Все существующие пациенты первоначально находятся в «Без категории».
Новые резервные копии ZIP v2 включают категории и рентгенограммы; приложение
также читает ZIP v1. Восстановление полностью заменяет каталог и снимки,
поэтому предварительно экспортируйте текущий архив. При отказе до фиксации
транзакции старые данные сохраняются; журнал файлов позволяет завершить
очистку после прерывания процесса.

Старое приложение не читает ZIP v2 и БД Room v2. Не устанавливайте старую
версию поверх новой базы; для возврата потребуется отдельно сохранённая копия v1.
Импорт TAR старой схемы v1 остаётся объединением: категория существующего
пациента сохраняется, новые пациенты добавляются без категории. TAR новой
схемы отклоняется; используйте ZIP v2.

Пределы ZIP: manifest 16 МиБ, изображение 512 МиБ, распаковка 20 ГиБ и
100 000 элементов. Полноэкранный просмотр использует уменьшенную копию для
ограничения расхода памяти; увеличение не гарантирует исходную детализацию
и не предназначено для диагностических измерений. Оригиналы не изменяются.

## Проверки и дизайн

`gradle :app:testVerificationUnitTest :app:assembleDebug :app:lintDebug` проверяет
данные, миграцию, резервные копии, цель импорта и геометрию просмотра.
`gradle :app:connectedVerificationAndroidTest` запускает проверки миграции и
интерфейса на подключённом Android-устройстве/эмуляторе. Они используют отдельный
пакет `com.clinicalphotoarchive.verification`, чтобы не затронуть клиническую базу.
Для release необходим существующий ключ подписи и переменные ANDROID_KEYSTORE_*
из конфигурации CI; новый ключ для обновления приложения не создаётся.

## Медицинская безопасность

Это исходная первая версия для личной локальной базы. Перед использованием в клинике проверьте требования вашей организации и применимого законодательства к персональным медицинским данным. Для следующей версии целесообразно добавить биометрический/PIN-доступ, шифрование экспортных резервных копий и аудит действий.
